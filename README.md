# 微信长期记忆 · 新内核预览

当前版本 `0.5.0-alpha.4`。需要 AstrBot ≥ 4.24.0 和微信 PC Hook 连接器。运行时仅使用 Python 标准库与 AstrBot 自带接口。

## 这次重构

建立独立的新数据库 `memory_vNext.sqlite3`，不修改、升级或删除旧 `memory.sqlite3`。V1/V2 引擎、旧表兼容、向量接口和主动音视频解析已移除。媒体仅保存待解析记录。

按功能组织：

| 位置 | 责任 |
| --- | --- |
| `core` | 群作用域、错误、SQLite 连接与新库 Schema |
| `features/archive.py`、`identity.py` | 消息与历史导入基础、群名、成员名称和称呼 |
| `features/memory.py` | 主张、事件、证据、修订版本和冲突审核 |
| `features/analysis.py` | 唯一模型协议、输入选取与输出校验 |
| `features/tasks.py`、`usage.py` | 持久任务、群内串行、断点与逐调用预算 |
| `features/retrieval.py` | 问题检索、身份消歧、权限过滤和审计 |
| `features/access.py`、`privacy.py` | 授权、退出与清除 |
| `features/transfer.py`、`commands.py`、`workbench.py` | 数据交换、私聊命令与管理查询 |
| `adapters` | AstrBot 事件、Provider、Hook 联系人和 HTTP |
| `application.py`、`main.py` | 组装服务与 AstrBot 入口 |

业务模块不导入 AstrBot。HTTP 和页面不执行 SQL。单一用途的操作保留在所属功能中，没有通用存储门面、框架或混入基类。

## 启用与旧数据重新导入

1. 停止旧插件调度，备份旧插件版本、配置及 SQLite 文件；运行中的数据库使用 SQLite backup API 制作一致副本。
2. 切换到本预览版本，配置 `enabled`、`allowed_rooms`、`admin_users` 和 `extraction_provider_id`。首次启动创建新库。
3. 工作台选择当前群，进入“导入与设置”，点击“直接导入 Hook Inbox”，程序从当前连接器读取路径并核对账号；也可以在页面输入旧库或 Inbox 在服务器/容器内的路径。开启 `backfill_enabled` 后才能导入。
4. 每次最多导入500条，再次选择相同路径继续。程序只读打开来源，并使用一致性快照；不会改动 Hook 游标。重复消息按当前群和原平台消息 ID 去重。
5. 核对数量、原话时间、成员名称与权限，然后主动启动历史分析。历史分析需开启 `reanalysis_enabled`，导入本身不调用模型。

导入原文、旧人工记忆（包括本人私聊添加的画像）、权限、退出设置和已确认称呼。自动 Claim、事件、旧运行记录、生产游标、向量与预览不导入。旧库和新库内部 ID 不相同，平台消息 ID 保持不变。

来源缺少消息 ID 或发言者时记入跳过清单；原文已经丢失的旧占位记录只能保留缺失状态，需从仍可用的 Inbox 恢复。不推测或补造原文。旧权限记录不覆盖新库中已经修改的设置。

## AI 如何使用记忆

在 AstrBot 实际发出模型请求前，插件按当前群、发言人和问题检索，并临时注入相关记忆。`retrieval_enabled` 默认开启。没有相关内容就不注入；同名歧义先提示澄清。AI 无需自行决定调用工具。

检索从全历史符合条件的主张中按问题筛选，使用词面排序。已撤回、已替代、待审核、过期、受限和退出成员资料不会用于召回；被标为受限原文的派生主张也被排除。不提供原文直通召回。

本人全局记忆仅在明确授权的群内、本人发起问答时使用，不跨群传播其他人的画像。第三方说法随来源标注，不当作本人确认。

## 分析与费用

四种任务共用一个协议与提交路径：新消息、历史、延期、画像。所有任务均持久保存，工作台的“分析任务”展示运行结果与模型调用；画像任务也在这里查看。

先预留预算，模型返回后先记录用量，再验证输出。覆盖不足最多缩批重试两次；超时与连接中断最多退避重试两次，每次请求都受预算约束。协议、权限、版本错误直接保留具体原因。未确认费用的调用保守记为“用量待核对”，不自动退款。

群内一次运行一个分析任务。暂停/取消不会承诺终止供应商已收到的请求，但返回结果不会提交；费用仍记录。恢复时若上次调用尚未返回，明确提示稍后再试。服务重启后任务暂停，默认手动恢复。

新消息进度、历史任务进度、逐成员巩固进度独立。超长消息按片段保存证据，片段完成前不推进整条消息。模型中无效项目记录原因并进入延期，正常项目仍可提交。

`dreaming_enabled` 默认关闭。启用后在配置时区的 `dream_hour` 后每日检查新消息和一个待巩固成员，仍受每日预算限制。低活跃群默认等待7天。自动延期重评默认关闭，开启后每条最多自动尝试两次。

预算按 UTC 日期重置，即北京时间08:00。价格为管理员配置的估算单价，无法代替供应商账单。

## 管理与隐私

成员卡按人聚合长期画像、近期事项、事件信息和待判断内容。名称优先管理员设置、群名片、昵称、明确自称；没有名称时显示账号 ID。同名不合并身份。通过工作台刷新群名和成员姓名，连接器离线时保留已有名称并显示具体错误。

记忆、称呼和事件编辑均要求 revision，冲突时刷新重做。人工修订保留版本，自动分析不能覆盖人工主张或人工事件摘要。事件补充必须指向已有同一场活动；同名不同场次不自动合并。近义与冲突由管理员审核。

私聊 `/wm` 查看本人画像、共享授权、群内退出和清除命令。画像退出会清除本人及相关派生画像，保留原文归档；`group erase` 同时清除本人原文。共同事件失去来源后隔离摘要，等待重整。清除会使相关任务和预览失效，并移除服务器临时导出文件。管理员另存的备份或下载副本需另行处理。

完整导出为服务器上的 JSONL 文件，包含所有当前群记录、证据、版本及数量清单，无静默行数截断。它是数据导出，不等同于可直接恢复运行的 SQLite 备份。

## 验证与回退

未编写任何自动化、临时或内联测试代码。当前仅完成必要的编译、静态分析、前端语法及本地开发库结构核对。真实 AstrBot / Hook / Provider / Dashboard 联调和生产数据副本验收尚未完成，因此不得按稳定版直接升级唯一正式实例。

回退恢复旧代码、旧配置和旧数据库。新库保留供后续重新导入，不自动反向合并到旧库。
